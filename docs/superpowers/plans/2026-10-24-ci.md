# CI on the Nix Dev Shell: Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** GitHub Actions runs `npm run check` inside the flake's dev shell, with Nix, the dev shell and npm packages restored from GitHub's cache instead of upstream, without keys, secrets or third-party actions, and fails when the pinned NixOS release is out of support.

**Architecture:**
- A local composite action installs Nix single-user from a hash-checked release tarball and adds a `file://` binary cache as a substituter; the cache keeps cache.nixos.org's signatures, so `require-sigs` with only the default key protects it.
- `seed-cache.yml` is the only workflow that writes caches; `check.yml` and `dependency-review.yml` only read (`cache-mode`).
- A temporary `ci-experiments.yml` proves the design on real runners in one push before the branch is finished.

**Tech Stack:** GitHub Actions (`actions/checkout`, `actions/cache`, `actions/dependency-review-action`, pinned by SHA), Nix 2.34.9 (the version nixpkgs 26.05 ships), nixpkgs `nixos-26.05`, Node 24, Vitest 5.0.3, Valgrind 3.26.

**Spec:**
- `docs/superpowers/specs/2026-10-24-ci-design.md` (decisions of 2026-10-24, proposals approved with this plan).
- `issues/0011-set-up-ci-check-and-dependency-review.md`, as Task 1 revises it.
- `docs/SPEC.md`, "Build and CI" and "Repository settings on GitHub", as Task 1 updates them.

## Global Constraints

- **Git:** branch `ci`; commit with `git -c commit.gpgsign=false commit`; never push, tag or sign; every commit message ends with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- **Actions:** only actions created by GitHub, each pinned by full commit SHA with the tag in a trailing comment (`# v5.0.1`), released at least 14 days ago; the local composite action `./.github/actions/nix`; no `pull_request_target`, no secrets, no retries.
- **Every workflow:** `permissions: contents: read`; `actions/checkout` with `persist-credentials: false`; `timeout-minutes` on every job; `cache-mode: write` only in `seed-cache.yml`, `read` in `check.yml` and `ci-experiments.yml`, `none` in `dependency-review.yml`; set for the whole workflow in `check.yml`, `dependency-review.yml` and `seed-cache.yml` (there with `write` only on the seed job), so a job added later reads; `runs-on: ubuntu-24.04`.
- **Nix:** version `2.34.9` and its tarball SHA-256 live only in `.github/actions/nix/action.yml`; install with `--no-daemon --no-channel-add --no-modify-profile`; `always-allow-substitutes = true` (added after E1: the `nodejs_24` wrapper would otherwise be built unsigned); never set `trusted=true`, `--no-check-sigs`, `require-sigs = false`, `accept-flake-config` or extra `trusted-public-keys`.
- **Cache keys and paths:** tarball `nix-installer-2.34.9-x86_64-linux` at `~/.cache/restlos/nix-installer`; store `nix-store-${{ hashFiles('flake.lock', 'flake.nix', '.github/actions/nix/action.yml', '.github/workflows/seed-cache.yml') }}` (restore key `nix-store-`) at `~/.cache/restlos/nix-store`; npm `npm-${{ hashFiles('package-lock.json', '.npmrc') }}` (restore key `npm-`) at `~/.npm`. Each key covers every file that changes what the seed puts into that cache. Restore and save list the same path.
- **npm:** `.npmrc` unchanged; `npm ci --prefer-offline` in `check`, plain `npm ci` in `seed-cache`; never `npx`.
- **Sandbox:** run every `nix` command on its own, never inside `&&`, `;` or a pipe.
- **REUSE:** workflow and action files start with `# SPDX-FileCopyrightText: 2026 The restlos-urlaubsplaner authors` and `# SPDX-License-Identifier: EUPL-1.2`; TS/JS as in the existing scripts; Markdown CC-BY-4.0.
- **Perf baseline:** never raised without the maintainer's approval; this plan doesn't change it.

## Review Focus

Covered by experiments in Task 6, since workflows have no unit tests:

1. **No store cache yet** (the first pull request, an evicted entry, a changed `flake.lock`): `check` still passes, falling back to cache.nixos.org. Exercised by the draft pull request's first `check` run.
2. **A changed dev shell** (a Dependabot `flake.lock` pull request): the exact store key misses, an older entry comes back through the `nix-store-` prefix, Nix takes the paths that still match and downloads the rest; `check` passes. Exercised by `probe-changed-shell`.
3. **A Nix version mismatch** (a `flake.lock` that ships another Nix): the action fails with the update instruction before `nix develop` runs. Exercised by `probe-version-guard`.
4. **A corrupt or altered tarball:** the install stops before extracting. Exercised in `probe-tamper`. This checks content only; a poisoned cache entry is kept out by the single writer and the cache scopes, not by any check after the restore.
5. **A save attempted in a read-only job:** the step logs and continues, and no entry appears. Exercised in `probe-cache-write`, `probe-cache-read` and `probe-cache-lookup`.
